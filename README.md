# Agent 工程哲学

> 《大模型应用工程哲学》的续作——二部曲的第二部。

第一本书的原始单元是模型，一个会出错的概率组件，你工程化的是建在它之上的应用。这本书换了一个原始单元：agent 这个自主角色——有岗位、有技能、有履历、有自己的工作环境。工程化的对象，从"用模型搭的应用"变成了"agent 本身"。这是比模型高一层的抽象，不是同一层的更深一刀。

核心视角：把 agent 当打工人看。

- 系统提示词，其实是 **JD**：岗位职责、权限边界、什么该做什么不该碰。
- skill，是简历上的技能条目；要跨 agent、跨环境复用，就得像 **证书** 一样可验证。
- 基础模型，像候选人的 **资历**：Opus 是资深专家，Haiku 是初级员工，岗位和能力要匹配。
- 长期记忆，是 **职业履历**：做过什么、踩过什么坑，跳槽也能带走。
- 带持久化卷的沙箱，是打工人的 **工作电脑**：环境稳定，今天的工作才能接到明天。

一套人力资源视角，串起 agent 工程的全部问题。和第一本一样，这本书关注的是"怎么想"，然后才是"怎么做"——不是 agent 框架手册，不是 multi-agent 编排速查表，而是一个人对"当 agent 成为软件的基本构件，工程该怎么做"的系统性回答。

## 与第一本书的关系

[《大模型应用工程哲学》](https://onenightcarnival.github.io/llm-engineering-philosophy/) 讲的是怎么和一个不靠谱的**函数**相处；这一本讲怎么和一个不靠谱的**同事**相处。

两本各自闭环，可独立阅读，但这一本站在前一本的肩膀上。凡是能在模型层讲清的（不确定性、声明式提示、类型契约、skill 可移植性），本书引用前一本，不重讲。
