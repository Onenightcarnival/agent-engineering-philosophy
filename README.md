# Agent 工程哲学

> [English](README.en.md) | 简体中文
>
> 《大模型应用工程哲学》的续作——二部曲的第二部。

第一本书从模型出发：模型是一个会出错的概率组件，工程要处理的是建在它之上的应用。这本书换了一个出发点：agent 这个自主角色——有岗位、有技能、有履历、有自己的工作环境。工程对象从"用模型搭应用"，转向"设计 agent 本身"。这是比模型高一层的抽象，不是同一层的更深一刀。

核心视角：把 agent 当打工人看。

- 系统提示词，其实是 **JD**：岗位职责、权限边界、什么该做什么不该碰。
- skill，是简历上的技能条目；要跨 agent、跨环境复用，就得像 **证书** 一样可验证。
- 基础模型，像候选人的 **学历**：Opus 是博士，Haiku 是刚毕业的本科生，岗位和学历要匹配。
- 长期记忆，是 **职业履历**：做过什么、踩过什么坑，跳槽也能带走。
- 带持久化卷的沙箱，是打工人的 **工作电脑**：环境稳定，今天的工作才能接到明天。

这套人力资源视角会把 agent 工程里的许多问题重新排一遍。和第一本一样，这本书先讲"怎么想"，再谈"怎么做"。它不是 agent 框架手册，也不是 multi-agent 编排速查表。它只回答一个问题：当 agent 进入软件系统的核心位置，工程该怎么做。

## 与第一本书的关系

[《大模型应用工程哲学》](https://onenightcarnival.github.io/llm-engineering-philosophy/) 讲的是怎么和一个不靠谱的**函数**相处；这一本讲怎么和一个不靠谱的**同事**相处。

两本各自完整，可以独立阅读。但这一本站在前一本的肩膀上。凡是能在模型层讲清的，不确定性、声明式提示、类型契约、skill 可移植性，本书引用前一本，不重讲。

### 第二章：模型不是员工

agent 的一生有个起点早于它自己。模型训练公司交付的不是员工，是候选人：预训练是通识教育，后训练是职业教育，模型分级是学历——而学历不说明岗位胜任。

### 第三章：岗位先于候选人

正确的顺序是先定义岗位，再选候选人。系统提示词不是咒语，是岗位合同；自主性来自清楚的边界。大多数 agent 跑不好，是岗位没定义清，不是模型不够强。

### 第七章：当团队里有很多 agent

团队的真问题不在 multi-agent 编排，而在岗位关系：分工、交接、授权、上下文隔离与共享。多 agent 写作是这一章的具体场景：一群 agent 同时生成再拼接，写不出好文章；不同判断岗位互相纠偏，再由主编岗位负责取舍，才像一个写作团队。

### 第八章：重新设计一种求真的团队

终章。agent 改变了组织的底层条件：更大的信息窗口、可临时生成的隔离岗位、更低的转岗成本、更完整的工作记录。多 agent 工程不做公司仿真，而是重新设计一种求真的团队：留下协调机制，删掉组织表演，用新机制处理 agent 自己的问题。事实判断流向最接近事实的岗位，最终责任落在能承担后果的人或组织身上。
