# skill 让整张图归位

"会用工具的动物"这个定义，缺口不在能力，在身份。它说清了 agent 能做什么：调工具、跑循环、把活干完。却说不清这个 agent 是谁。同一段循环，换一个目的就是另一个 agent，而它没有给"目的"留位置。

skill 出现的时候，缺口补上了一角，也让那套散着的零件开始归位。

## 从 skill 这一点开始

skill 容易被看成又一个工具。但它和工具不是一类东西。工具是一次调用，用完即弃，下一轮对话不会跟着 agent 走。skill 有名字，可以复用，可以从一个 agent 挂到另一个 agent 上，效果不会差太远。一个可命名、可复用、可迁移的能力单元，正像技能长在一个人身上。会做 PPT 的人，换一家公司也会做 PPT。

到这里冒出一个念头：skill 像简历上的一条。

这个念头不解决任何工程问题，它只是一点火光。但就是这点微光，照见了一个更大的联想：如果 agent 身上的能力可以按简历条目来理解，那 agent 这个整体，也许也该按一个人来理解，而不是按一段会调工具的程序来理解。

换个抽象看同一个东西，多数时候什么也看不出。这一次不一样，借着这点光，整张图忽然归了位。

## 顺着这条线，零件一个个对上

把 agent 当一个人来看，原先各自孤立的零件开始自动落位。

系统提示词落位成 JD。它写的本就是这个岗位干什么、汇报给谁、什么能碰什么不能碰。它是一份岗位职责说明，不是一段要反复调试的咒语。

模型分级落位成学历。Opus、Sonnet、Haiku 的差别，对应博士、硕士、本科的段位与价码。派活要看学历：让最贵的人去做每天一次的格式转换是浪费，让最便宜的人去扛长链推理是冒险。

长期记忆是职业履历。做过什么、踩过什么坑、某个客户的偏好是什么，都记在案，换一份工作还能带走。

带持久化卷的沙箱是工作电脑。文件、依赖、配置、半成品工程都在这台机器上，今天调好的环境明天还在，今天的活可以接着明天干。

零件对上标签，还算不上什么，比喻谁都能凑。让这套看法立住的，是零件之间的关系也跟着对上了。JD 约束这个人该用哪些 skill，而不是把简历上的所有本事都使出来。学历决定该把哪一档的活派给他。履历跟着人走，换岗不丢。这些关系不是事后硬安进去的。把"一个人"这个抽象套上去，它们自己就浮出来了。

## 一套现成的抽象

agent 这一层需要的抽象，不用发明，现成就有一套。

零件能落位，不是凑巧。agent 这条路线本来就是照着人设计的——语料是人写的文本，对齐靠人的反馈，连"助手""推理""记忆"这些词都从人身上借来。一个照着人造出来的东西，本就该用一套抽人的成熟办法去看。

抽"人"的办法不止一种：心理学抽人格，经济学抽效用，生物学抽有机体，各抽各的一面。能对上 agent 的，是抽"人作为劳动力"的那一套——岗位、技能、学历、履历。它有个现成的名字，人力资源。HR 抽的那个切面，恰好就是 agent 占的位置：一个可雇佣、能上岗、留得下记录的工作单元。切面对上了，零件才会一个不剩地落位，而不是勉强往跟前凑。

用它去看 agent，"prompt 写得好不好"变成"JD 写得清不清楚"，"该用哪个模型"变成"这个岗位配多高的学历"——问题被重新排了一遍。这套抽象立不立得住，不看这里怎么说，看往后每一章从它推出来的工程决策站不站得住。

到这里，图归位了。
