# 系统提示词不是咒语

系统提示词最常被当成咒语来写。

加一句"你必须"，加一句"这非常重要"，加一句"请一步步思考"，反复试措辞，看哪一种念法能逼出想要的行为。这是把 prompt 当成对黑箱的祈祷：不知道里面怎么运作，只能换着词去求它。

## 咒语思维错在哪

咒语思维的毛病，是它默认问题出在措辞上。行为不对，就再改一句话、再加一个强调词。可大多数时候，行为不对不是因为话没念对，是因为岗位根本没说清。

把同一份系统提示词当岗位合同来看，写法立刻变了。它要写的是这个岗位的四件事：职责，做什么；权限，能碰什么；边界，不能碰什么；汇报路径，什么时候上报、向谁交付。这些都是岗位陈述，不是对候选人的咒求。一份好 JD 不靠"非常重要"这种词起作用，靠的是把岗位本身说清楚。

prompt 在字面上该怎么写、声明式为什么好过命令式调教，这在模型那一层已经讲过（见第一本）。这里讲上一层：用"岗位合同"组织 prompt 里该放什么内容。抽象对了，措辞的焦虑自然就退场了。

## 写不出 JD，是岗位没想清

于是有一条朴素的自检：如果你写不出一份清楚的 JD，问题不在措辞，在你自己还没想清这个岗位是干嘛的。

念咒能掩盖这件事一阵子——靠不断微调，偶尔也能蒙对几次行为。但岗位没想清这个根，靠加强调词补不上。把力气从"换一种念法"挪到"把岗位说清楚"，是从咒语思维转到岗位合同思维的全部。
