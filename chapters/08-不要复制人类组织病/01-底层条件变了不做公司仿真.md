# 底层条件变了，不做公司仿真

上一章讲多 agent 团队怎么设计。这一章先退一步问：为什么不能直接照搬人类组织。

把 agent 当打工人看，是为了让岗位、能力、履历、环境、责任这些工程对象重新排好位置。不是让你照着公司组织结构，给 agent 安一堆职级和部门名。

## 组织的成本结构变了

人类组织不是凭空长成现在这样。它有层级、有汇报、有审批，很大一部分来自人脑的限制：一个人能同时处理的信息有限，能稳定切换的角色有限，能记住的上下文有限，能扛的心理压力也有限。组织里很多看着像管理智慧的东西，其实是这些限制的补丁。

agent 进来以后，这几条限制不再原样成立。

一是窗口变大，中间层被削弱。人类组织需要大量中间层来压缩信息：一线接触事实但消化不了全局，高层负责取舍但离事实太远，中间层把事实压成汇报、把细节压成结论。一个 agent 如果能稳定处理很大的材料集合，就可以直接读 trace、读原始材料、读交接物，不必等一层层汇报把世界压扁。组织形态会因此更扁：事实更快流向能判断的位置，判断也更快回到执行现场。

但这里有个前提，容易被"窗口变大"这句话盖过去：能不能吃下一大堆材料，本身就是一档段位。给一个弱模型塞满上下文，它消化不了，还会被噪声带跑，反不如原来那层预消化——中间层那份把世界压成结论的活并没有消失，只是被你假装消失了。扁平化是有条件的：岗位得配上够格的段位，削掉中间层才成立。段位不够，你不是削了中间层，是把它那份活压给了一个干不动的人。

二是角色可以临时生成。人很难把角色隔离干净——刚写完一段就审自己的稿，审查会被写作时的偏好带跑；刚提出一个方案就给自己做风险评估，评估会顺手替方案找理由。agent 没有这个包袱。主 agent 可以拉起一个批判 agent，只给它必要材料，不给它主写 agent 的自我辩护；也可以拉起一个事实校验 agent，让它从原始材料出发，不从结论出发。这种 sub agent 不需要长期存在，不需要完整履历，不需要进编制，它只是一次干净的判断环境。

三是转岗成本低，通才更常见。模型本身有很宽的通识，skill 可以临时加载，工具可以按岗位授权，履历可以提炼和迁移。人类员工跨岗位常要重新学习、重新适应、重新搭环境；agent 换岗位，很多东西可以复制、裁剪、重组。它不一定马上胜任，但转岗成本低得多。

## 别给 agent 套公司外壳

底层条件变了，就不该把公司当模板整套搬来。

公司仿真最常见的样子，是给 agent 团队安上经理、主管、会议、汇报、审批、日报。看着完整，其实只复制了形式。人类组织需要这些仪式，是因为人会遗忘、会隐瞒、会争功、会回避责任，也因为信息在组织里传得慢、失真多。一个 trace 已经记清楚的过程，不必再写一份向上表演的周报；一个权限系统已经禁止的动作，不必再走层层口头审批；一个完成即销毁的临时角色，不需要一套长期职级。

更糟的是，外壳会把人类组织的失败规律一起带进来：让层级替代事实，让汇报替代工作记录，让流程感替代责任。

## 每个岗位都要审计

把 agent 当打工人看，不等于岗位越多越好。

岗位是工程对象，不是组织装饰。它要写清职责、权限、交付物和升级条件。但切得过细，本身就是复杂度。一个通才 agent 本可以在同一工作面上完成的事，拆成三个岗位之后，就多了三份交接物、三段上下文压缩、三处责任边界——拆分没带来更好的判断，只带来更多接口。

过去很多岗位被切出来，不是因为任务天然要这么拆，而是因为人处理不了：有人只做汇总，因为别人读不完材料；有人只做协调，因为信息传得慢；有人只做审批，因为组织不信任一线。把这些岗位原样搬给 agent，等于把人类局限造出的复杂度也搬进来。

所以每拆一个岗位，都该问一遍：这个拆分来自任务结构，还是来自人脑带宽？是为了事实独立性，还是只为了组织感？是降低风险，还是制造审批感？交接成本是不是小于拆分收益？虚假岗位删掉，真实边界留下。

## 从约束出发，不从公司形状出发

多 agent 团队该从约束出发设计。问题是分工，就设计岗位边界；问题是交接，就设计交接物和验收标准；问题是风险，就设计授权和升级路径；问题是质量，就设计 eval 和工作记录；问题是责任，就设计最终收束点。

这些约束在人类组织里也有，但它们靠协作本身成立，不靠公司这个外壳成立。公司只是历史上承载这些约束的一种形态。agent 团队可以借它的经验，不必复制它的外壳。下一篇先讲该保留的那部分。
