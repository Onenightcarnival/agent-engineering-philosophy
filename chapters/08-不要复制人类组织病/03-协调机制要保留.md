# 协调机制要保留

不复制公司，不等于抛掉组织经验。

人类组织里有一部分机制用来处理分工，不是用来对付人性。只要有多个角色一起工作，这些机制就不会消失。把人换成 agent，问题的材料变了，约束还在。

## 分工要求边界

多个 agent 一起工作，先要有岗位边界。

边界不清，问题不会因为 agent 没有情绪而消失。规划 agent 如果同时负责执行和审查，会对自己的方案手软；执行 agent 如果不知道哪些决策必须上报，就会在畏缩和越权之间摆动；审查 agent 如果没有明确的否决标准，就会变成礼貌性点评。

这些是分工问题，不是人性问题。分工一旦出现，边界就必须出现。第三章讲单个 agent 的 JD，到了团队层，还要把 JD 之间的关系写清楚。

## 交接要求契约

第二个要保留的是交接契约。

人类团队里，很多事故发生在两个人之间；agent 团队里也是一样。一个 agent 的输出成为另一个 agent 的输入，格式、范围、置信度、未决问题如果没写清，下游就会拿着含糊输入继续生成，把错误一路放大。

交接物要像接口一样设计。不要把上游说过的话整包发给下游，要明确给出下游需要的结构化信息：结论是什么，依据是什么，哪些地方不确定，哪些动作不能做，什么情况必须退回。

这类机制在公司里叫流程，在工程里叫契约。名字不重要，约束重要。

## 授权要求升级路径

第三个要保留的是授权和升级路径。

一群 agent 不能凡事都问人。那样只是把很多节点挂在一个人类瓶颈上，团队吞吐并没有提高。但也不能让每个 agent 各自决定不可逆动作。那不是自主，是失控。

好的团队设计要写清：哪些决定本岗位自己处理，哪些决定交给更高资历的 agent，哪些决定必须交给人。触发条件也要明确：高不确定性、不可逆动作、越过岗位边界、影响真实用户或真实资产。

这些协调机制都该保留。它们不是人类组织的装饰，而是分工协作的骨架。该删的，是另一类东西：为人性失败打上的补丁。
