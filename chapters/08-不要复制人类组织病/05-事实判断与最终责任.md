# 事实判断与最终责任

多 agent 团队里最容易混在一起的，是两种权力：事实判断权和最终否决权。

事实判断权回答“这件事到底是不是这样”。最终否决权回答“这个后果我接不接受”。前者应该流向最接近事实的岗位，后者必须落在能承担后果的主体身上。

把这两件事混在一起，人类组织已经吃过很多亏。agent 团队不能再复制一遍。

## 谁接近事实，谁主导事实判断

事实判断不随层级发放。

一个刚完成检索的事实校验 agent，可能比主编更知道某个引用靠不靠得住。一个刚跑完测试的执行 agent，可能比规划 agent 更知道方案哪里会坏。一个专门审查安全边界的 agent，可能比负责交付的 agent 更清楚哪个动作不能放行。

如果最终收束岗位无视这些局部判断，只因为自己在上游或更高层就强行裁决事实，它就犯了人类组织里的老错：用位置替代判断。

健康的 agent 团队应该让事实判断沿着证据流动。谁掌握证据，谁对那个局部有更高发言权。工作记录、trace、eval、原始材料，才是事实判断的依据。

## 谁承担后果，谁保留最终否决

但事实判断不是全部。还有后果。

一个 agent 可以判断某个动作大概率正确，但如果这个动作会发给真实客户、动真实账务、删除真实数据、承诺真实交付，最终决定不能交给一个不承担后果的东西。

这不是因为人永远更懂。很多局部事实上，agent 可能更准、更快、更稳定。最终否决留给人或组织，是因为后果要落在一个能被追究的主体上。AI 不能坐牢，不能破产，不能拿自己的信誉抵押，也不会为后果痛。

最终担责点可以说：“这个风险我不接受。”它不该说：“因为我负责，所以你的事实判断是错的。”前者是在承担后果，后者是在冒充懂行。

## 工作可以拆，影响不能拆

多 agent 最诱人的地方，是工作可以拆。一个任务 fan-out 成许多子任务，并行处理，再收回来。能力、时间、上下文都可以拆。

但影响不能拆。一个系统发出的错误结论、造成的损失、对外许下的承诺，不会因为工作拆成十份，就也拆成十份摊薄。用户看到的是一个系统，后果也会合成一个整体。

好的多 agent 设计必须有单一的最终担责点。这个点可以是人，也可以是一个有法律和组织责任的实体，但不能是“这几个 agent 都参与了，所以大家各担一点”。那等于谁都没有承担到底。

事实判断与最终责任分开，整套团队才站得住：事实流向最懂的岗位，最终否决留给能担责的人或组织。最后一篇收束全书。
