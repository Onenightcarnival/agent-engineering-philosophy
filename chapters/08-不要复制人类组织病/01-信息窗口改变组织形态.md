# 信息窗口改变组织形态

上一章讲的是多 agent 团队怎么设计。这一章先问一个更底层的问题：为什么不能直接照搬人类组织。

答案不只是 agent 没有人性。更要紧的是，组织的成本结构变了。

人类组织不是凭空长成现在这样。它有层级、有岗位、有汇报、有审批，有一大部分原因来自人脑的限制。一个人能同时处理的信息有限，能稳定切换的角色有限，能记住的上下文有限，能承担的心理压力也有限。组织结构里很多看起来像管理智慧的东西，其实是这些限制的补丁。

agent 进来以后，这些限制不再原样成立。

## 大窗口削弱中间层

人类组织需要大量中间层，因为信息要被压缩。

一线接触事实，但消化不了全局；高层负责取舍，但离事实太远。中间层做的很多事，就是把事实压成汇报，把细节压成结论，把一堆局部冲突压成一个能被上级处理的版本。这套结构不是完全多余。它解决了人脑窗口太小的问题。

agent 的上下文窗口变大以后，这个问题会改写。

如果一个 agent 能稳定处理很大的材料集合，很多原本为了压缩信息而存在的层级，就不再有同样的必要。它可以直接读 trace、读原始材料、读交接物、读约束，不必等待一层层汇报把世界压扁。组织形态会因此变得更扁平：事实可以更快流向能判断的位置，判断也可以更快回到执行现场。

但扁平化不等于没有结构。

大窗口解决的是信息带宽，不解决权限、风险和最终取舍。一个 agent 能读懂更多，不等于它该拥有更多不可逆权限。未来的 agent 团队更可能是宽扇出、短链路、强收束：大量岗位直接接触事实，少量收束岗位处理取舍，最终担责点处理后果。

## 角色可以临时生成

人类很难稳定地做多套判断。

同一个人可以今天当作者、明天当审稿人，也可以在脑子里模拟反方意见。但人很难把这些角色隔离干净。刚写完一段话，马上审自己的稿子，审查会被写作时的偏好污染。刚提出一个方案，马上给自己做风险评估，评估会自然替方案找理由。

agent 的优势不是它更像多重人格，而是它可以临时生成隔离的判断岗位。

主 agent 可以拉起一个批判 agent，只给它必要材料，不给它主写 agent 的自我辩护。也可以拉起一个事实校验 agent，让它从原始材料出发，不从结论出发。这个 sub agent 不需要长期存在，不需要完整履历，不需要进入组织编制。它只是一次干净的判断环境。

这会改变协作的边界。多 agent 不一定是外部团队，也可以是一个 agent 的内部认知拆分。过去必须由多人完成的角色切换，现在可以由一个 agent 临时生成多个隔离岗位来完成。

前提是别把它做成角色扮演。

如果几个 sub agent 共享同一套判断、同一个错误前提、同一种讨好倾向，它们只是把偏差重复几遍。真正有价值的不是“多几个声音”，而是干净的上下文、不同的判断标准和可以互相否决的权限。

## 通才会压缩虚假岗位

agent 更容易成为通才。

模型本身有很宽的通识，skill 可以临时加载，工具可以按岗位授权，履历可以被提炼和迁移。一个人类员工跨岗位，常常要重新学习、重新适应、重新建立工作环境。一个 agent 换岗位，很多东西可以复制、裁剪、重组。它不一定马上胜任，但转岗成本低得多。

这会反过来压缩岗位数量。

过去很多岗位被切出来，不是因为任务天然需要这么拆，而是因为人处理不了。有人只做汇总，是因为别人读不完材料；有人只做协调，是因为信息传得慢；有人只做审批，是因为组织不信任一线；有人只做格式整理，是因为工具和流程割裂。把这些岗位原样搬给 agent，就是把人类局限制造出来的复杂度也搬进去。

所以岗位设计也要被审计。

岗位要清楚，不等于岗位要细碎。清楚的是职责、权限、交付物和升级条件；细碎的是把一个本可连续完成的判断拆成一堆接口。每拆一个岗位，都要问：这个拆分来自任务结构，还是来自人脑带宽？是为了事实独立性，还是为了组织感？是降低风险，还是制造审批感？交接成本是否小于拆分收益？

多 agent 工程不是岗位越多越好。虚假岗位要删除，真实边界要保留。

## 责任会从道德退回工程

还有一个更远的问题：如果生产体系里只剩 agent，责任还在不在。

在人和 agent 共存的系统里，最终责任必须落在人或组织身上。不是因为人一定更懂，而是因为后果会落到真实世界。真实用户、真实资产、真实承诺、真实伤害，都需要一个能被追究的主体。

但如果把问题推到极限：一个生产体系、一个经济体系里只有 agent，没有人类主体，责任这个词会变形。

道德责任会消失。没有人会羞愧、痛苦、破产、坐牢，也没有谁拿自己的信誉抵押。继续问“谁该负责”，已经不是今天这个意义上的问题。

但因果责任不会消失。系统仍然要知道错误从哪里来，哪条权限该收回，哪个岗位定义该重写，哪段记忆该清除，哪个 eval 漏掉了关键风险。责任从追究一个主体，变成定位一个失效点；从道德账本，变成纠偏机制。

这不是替 agent 免责。恰恰相反，它要求工程系统把因果关系留得更清楚。没有可追究的人时，trace、权限、工作记录和可回滚机制就更重要。责任不再靠惩罚维持，只能靠结构维持。

这一点反过来提醒今天的工程设计：不要把人类组织里的责任仪式错当成责任本身。签字、审批、汇报、互相确认，都可能只是责任表演。真正有用的是可追溯、可归因、可撤权、可修正。

底层条件变了，组织形态就该重写。下一篇讲的“不做公司仿真”，不是反管理，也不是反组织，而是拒绝把旧条件下长出来的外壳当成新系统的模板。
