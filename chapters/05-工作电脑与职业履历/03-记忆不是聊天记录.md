# 记忆不是聊天记录

工作电脑管的是连续的工作面，履历管的是连续的记录。后者就是长期记忆。

但长期记忆最常见的理解是错的：把它等同于"把所有聊天记录都塞进上下文"。仿佛记得越多越好，最好无限长，一句不漏。这不是记忆，是囤积。

## 履历是提炼，不是流水

想想职业履历是什么。它不是你在公司说过的每一句话、开过的每一场会的逐字稿。它从这些经历里提炼出来：做过哪些项目、得到什么结果、学会了什么、在哪摔过跤。它短，但每一条都能被检索、被用上。

长期记忆该长成履历这个样子，不该长成聊天记录。把原始对话流水一股脑保存下来，看着信息全，实则没法用——关键判断淹没在寒暄和试错里，要用的时候捞不出来，塞进上下文还挤占空间。有用的记忆是结构化的提炼：把"发生了什么"压缩成"学到了什么"，留下能复用的结论，丢掉一次性的过程。

## 设计记忆是设计"记什么"

于是记忆系统的核心，不是"能存多少"，是"记什么、怎么提炼、怎么检索"。

存量从来不是难点，硬盘很便宜。难的是判断哪些值得写进履历，怎么把一段经历提炼成可复用的结论，以及未来需要时怎么准确地找回来。上下文窗口该怎么管、什么时候该把信息移出窗口，这些在模型那一层已经讨论过（见第一本）；这一章站在上一层看：记忆不是无限上下文的同义词，而是一个 agent 的履历——经过筛选和提炼，才配叫履历。

而履历一旦建立，它就不只是被查阅的档案。它会反过来改变这个 agent 怎么工作。这是下一篇，也是这一章的落点。
