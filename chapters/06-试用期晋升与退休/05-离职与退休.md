# 离职与退休

agent 的生命周期有终点。一个 agent 被停用、被替换、被淘汰，不是 kill 掉进程就完了。

像员工离职一样，它该走一套流程。少了这套流程，留下的不是干净的空位，是悬而未决的尾巴。

## 下线是一次有流程的离职

至少有四件事要做。

交接。它手上没干完的活、它知道而别处没有的上下文，要传给接手的 agent 或人。一个 agent 直接消失，它脑子里和它电脑里那些没沉淀下来的东西，就跟着消失了。

归档。它的产物、履历、有价值的工作记录要留存下来，不随实例销毁而蒸发。这些是组织的资产，不是这个 agent 的私产——它退休，资产该入库，不该陪葬。

权限回收。它持有的工具访问、数据读写、对外授权，要收回。这一条最容易漏，也最危险：一个已经停用、却仍然持有权限的 agent，是一个悬空的安全口子。第三章把权限当 JD 的一部分发出去，离职时就得对应地收回来。

记忆处理。它的长期记忆怎么办——哪些并入组织资产、哪些直接销毁、哪些涉及敏感信息必须清除。记忆是履历，履历里可能有不该留、也不该随便扩散的东西。

## 终点也是设计的一部分

把这四件事做全，agent 的下线才是一次干净的离职，而不是一次留着隐患的进程终止。

生命周期有始有终。前面几章设计的是怎么让一个 agent 出生、上岗、成长，这一篇说的是怎么让它体面地退出。一个只设计了入职、没设计离职的系统，会随着 agent 来来去去，积下越来越多悬空的权限、丢失的上下文和无人认领的记忆。终点也是设计的一部分。

至此，一个 agent 从出生到退休的完整一生讲完了。再往下，问题从"一个 agent"变成"很多 agent 在一起"。
