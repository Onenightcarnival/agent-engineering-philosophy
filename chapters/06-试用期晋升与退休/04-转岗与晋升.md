# 转岗与晋升

agent 也会换岗，也会被委以更重的职责。这时候要问：什么能跟着走，什么不能？

## 有些东西可迁移，有些不能无损搬家

职业证书级的 skill 可以迁移，履历可以参考——这两样跨岗位仍有价值。一个会做代码审查的 skill，换个项目还能用；一段"这类任务上踩过什么坑"的履历，换个岗位也有借鉴。

但岗位经验不能无损搬家。一个客服岗 agent 攒下的、对这家公司客户脾性的理解，对这套内部工单系统的熟悉，换到风控岗，大部分作废。那些经验是为旧岗位长出来的，绑在旧岗位的上下文里。这正对应第四章那条线：上岗培训是岗位特定的，职业证书才是可迁移的——转岗时，前者大半要重来，后者能带走。

## 晋升不是把旧 agent 放大

晋升也一样。给一个 agent 更重的职责、更高的资历，不是把原来那个原样放大一圈。

它是一次重新组合：重写 JD（职责变了），可能换一档更高的模型（资历要匹配新职责），保留可迁移的部分（证书 skill、履历），重建岗位特定的部分（新的上岗培训、新的工作环境）。把晋升想成"同一个 agent 变强了"，会漏掉重写岗位这一步，结果是一个揣着旧 JD 干新活的 agent——又回到第三章那个岗位错配的老问题。

所以转岗和晋升的正确动作，都是按新岗位重新组合：迁移能迁移的，重建岗位特定的。能不能搬，取决于那样东西当初是为岗位长的，还是为这个角色本身长的。
