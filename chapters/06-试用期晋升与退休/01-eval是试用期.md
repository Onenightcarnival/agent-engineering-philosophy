# eval 是试用期

评估一个 agent，最常见的做法是看排行榜：哪个模型在通用基准上分高，就认为它更好。

这是把 eval 当成模型选秀。但对一个具体的岗位，要回答的问题根本不是"这个模型在通用题上多强"，是"这个 agent 放到这个岗位上，能不能把活干合格"。这两个问题的答案常常不一致——通用榜首未必是你这份活的最优解，上一章讲学历不是岗位胜任，就是这个意思。

## 试用期考的是岗位，不是名次

人类招聘有试用期，正是因为简历名次说明不了岗位胜任。试用期不看学历排名，看的是把人放到真实岗位上、做真实的活，合不合格。

eval 该是 agent 的试用期，而不是它的高考排名。这意味着 eval 要按岗位来设计：用这个岗位的真实任务、真实数据、真实的合格标准去考它，而不是搬一套与岗位无关的通用榜单。一个发票抽取岗的 eval，该考它在真实发票上的抽取准确率和该上报时上不上报，不该考它的通用推理得分。

## 脱离岗位的 eval 测不出胜任

由此有一条判断：脱离岗位的 eval，测不出一个 agent 好不好，只测得出它的通用段位。

通用段位是选型时的一个输入（见上一章），但它不是岗位胜任的结论。把通用 eval 的高分当成"这个 agent 能胜任我的岗位"，是在用试用期之前的简历，代替试用期本身。真正要建立的，是一套贴着岗位长出来的考核——它考的是这份活干得怎么样，不是这个候选人在通用题上排第几。
