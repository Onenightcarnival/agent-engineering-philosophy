# 能力资产要可复现

证书可信，归根到底是因为背后的能力可复现：同样的人、同样的考核，结果稳定。换个考官、换个考场，不会一次过一次挂。

skill 要成为资产，靠的是同一件事。一个 skill 如果只在某台机器、某个时刻、某次碰巧凑齐的依赖下能跑，那它不是能力资产，是一段一次性脚本。可复现，是 skill 从"个人手艺"变成"可转移资产"的那道门槛。

## 可复现要写实哪些东西

让一个 skill 可复现，要把平时藏在环境里、靠默契补齐的东西，全部摆到明面上：

```
skill: 财报表格校验
依赖：列出所需的库与版本，不依赖全局环境里碰巧装着的东西
环境：声明运行所需的运行时与配置，能在干净环境里重建
输入输出约定：输入是什么格式、输出是什么结构，明确且稳定
测试样例：给定若干输入与期望输出，换个地方也能验证它仍然有效
```

这四样——依赖、环境、输入输出约定、测试样例——决定了一个 skill 能不能从"我这儿能跑"，变成"换个地方也能跑，而且能验证还在正常工作"。

类型契约与可移植性为什么是这种可靠性的基础，第一本已经讲过（见第一本）。这里把它放回 skill 这个能力单元上看：约定写实，依赖声明清楚，样例给齐，这个 skill 才经得起别的 agent 拿去用，也经得起未来的自己回来改。

## 不可复现的能力是负债

反过来说，一个不可复现的 skill，不只是"还不够好"，它是负债。

它会在某次环境漂移后悄悄失效，而你以为它一直好好的；它没法被安全地复用，每挂到一个新地方都要重新调一遍；它也没法被验证，你不知道它今天给出的结果还对不对。攒了一堆这样的 skill，看着像能力越来越厚，实则是隐患越积越多。

所以衡量一项 skill 值不值得留下，标准不是"它能不能跑出一次漂亮结果"，是"它能不能在别处、在以后，稳定地跑出同样的结果"。能，它就是资产；不能，趁早别把它当资产。
