# skill 不是工具

第一章说，skill 像简历上的一条。要让这一条成立，先得把 skill 从工具堆里拆出来：它和工具不是一类东西，混在一起看，agent 的能力就讲不清。

## 工具是一次调用，skill 是一项能力

工具是一次调用。给定输入，返回输出，无状态，用完即弃。查一次天气、发一次请求、跑一次计算，都是工具。它是 agent 够到外部世界的手，本身不构成“会做某件事”。

skill 是一项能力。它把做某一类事所需要的方法、流程、知识封装起来，有名字，可复用，可以从一个 agent 挂到另一个 agent 身上，效果不会差太远。这像技能长在一个人身上——会做 PPT 的人换家公司还会做 PPT，能力跟着人走，不跟着某一次任务走。

两者的区别，像“会用螺丝刀”和“会装修”。螺丝刀是工具，装修是技能。一个会装修的人当然要用很多工具，但你雇他，雇的是“会装修”，不是“持有一把螺丝刀”。

## agent 的能力由 skill 定义

这个区分一旦立住，看 agent 的眼光就变了。

一个 agent 可能有很多工具的访问权——能查库、能发信、能跑脚本。但这些只是它手边的工具箱，不等于它“会做什么”。定义它能力的，是它掌握的 skill：会做对账、会写周报、会做代码审查。工具是手，skill 是手艺。

所以给 agent “加能力”，多数时候不是再接一个工具，是整理出一项 skill。把“这类事该怎么做”做成一个可命名、可复用的单元，agent 的能力才长了一截。skill 能跨 agent 迁移而效果不塌，第一本讲可移植性时已有论述；在“一个人”这个抽象里，它的位置是手艺，是简历上写得出来的那一条。

手艺从哪来？要么是公司教的——上岗培训；要么是过往攒下、走到哪带到哪的——职业证书。
