# 岗位特定的 skill 是上岗培训

skill 的第一副面孔朝内，是上岗培训。

新人入职，总有一段时间在学这家公司特有的东西：内部系统怎么登、报销流程怎么走、代码库的规范是什么、这个领域的黑话指什么。这些知识换一家公司就作废，但它们让人在这个岗位上从"会通用技能"变成"能干这里的活"。

## 把岗位知识沉淀成 skill

给 agent 做上岗培训，就是把岗位特有的流程、领域知识、内部工具用法，封装成 skill。

这件事的反面，是把所有岗位知识一股脑塞进系统提示词。一开始还行，越塞越长，到后来 JD 里一半是岗位职责、一半是"我们公司的对账规则第十七条"。岗位说明和操作手册混成一团，改一处要在长文里翻找，复用更无从谈起。

沉淀成 skill 就清爽了。岗位胜任力从"写死在 prompt 里的一大段文字"，变成"可维护、可版本化、可复用的能力模块"。对账规则改了，改那个 skill，不动 JD。新来一个同岗位的 agent，把这套上岗培训挂上，它就上手了。

## 上岗培训是岗位特定的

要记住上岗培训的边界：它是岗位特定的，不天然可迁移。

公司内部的流程、私有系统的用法，离开这家公司就没有意义，也不该指望它在别处通用。这不是缺陷，是分工——上岗培训本就为某个具体岗位而设。它和下一篇要讲的"职业证书"分属两类，设计的标准也不同。混淆这两者，会让人要么把岗位专属的东西硬做成通用（白费力气），要么把本可通用的能力锁死在一个岗位里（浪费资产）。

先认清哪些 skill 是上岗培训——只在这个岗位、这家公司有效。剩下那些能走到哪带到哪的，才是证书。
