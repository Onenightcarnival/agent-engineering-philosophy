# 可迁移的 skill 是职业证书

skill 的第二副面孔朝外，是职业证书。

会计证、驾照、各类职业资格——它们的价值在于跨公司、跨环境被认可。换一家公司，证还是那张证，效力不变。可迁移的 skill 就是 agent 的证书：它不绑定某个 agent、某个环境、某个岗位，挂到哪里都能用，效果不会塌。

## 证书为什么能跨环境

证书能跨环境，靠的是一件事：可验证。

一张驾照之所以在任何城市都被认，是因为它背后有一套标准化的考核，谁来考、在哪考，结果都对得上。一个 skill 要够得上"证书"这个级别，也得满足同样的条件——它得能跨 agent、跨环境、跨岗位被复用，而且效果可以被检验，不是"在我这儿好像能用"。

这给 skill 的设计提了一条硬要求：不依赖某个特定 agent 的隐藏上下文。如果一个 skill 只有在某个 agent 攒了一堆它没明说的前提时才跑得起来，换个 agent 就废，那它就不是证书，顶多是这个 agent 的个人习惯。证书必须自带它需要的一切——前提、依赖、用法都写在明面上，谁拿去都能照着用。

## 两类 skill，两套标准

到这里，skill 的两副面孔清楚了：上岗培训是岗位特定的，职业证书是可迁移的。

它们的设计标准不一样。上岗培训只要在本岗位有效就够，可以放心依赖公司内部的约定。职业证书要在任何地方都有效，就必须把对内部约定的依赖全部砍掉，做到自足、可验证、可移植。

设计一个 skill 之前，先问它该做成哪一类。当成上岗培训做，就别强求它通用；当成证书做，就别让它偷偷依赖本地环境。无论哪一类，决定它是资产还是负债的，都是同一件事——可复现。这是下一篇。
