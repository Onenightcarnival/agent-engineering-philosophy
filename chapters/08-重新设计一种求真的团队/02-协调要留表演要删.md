# 协调要留，表演要删

不照搬公司，不等于把组织经验全扔了。人类组织里的机制分两类：一类处理分工，一类处理表演。前者要留，后者要删。

表演不只是开会和写汇报。它还包括用流程制造安全感，用签字稀释责任，用层级压过事实，用态度代替产物。这些机制在人类组织里未必全无用处。它们常常是在信息不完整、信任不足、权力不均的时候，让组织勉强运转。但 agent 团队不该继承这些旧条件。

## 处理分工的机制要留

只要有多个角色一起干活，处理分工的机制就不会消失。把人换成 agent，材料变了，约束还在。

先是岗位边界。边界不清，问题不会因为 agent 没情绪就消失。规划 agent 如果同时管执行和审查，会对自己的方案手软；执行 agent 如果不知道哪些决策必须上报，就在畏缩和越权之间摆动；审查 agent 如果没有明确的否决标准，就变成礼貌性点评。第三章讲单个 agent 的 JD，到了团队，还要把 JD 之间的关系写清楚。

再是交接契约。很多事故出在两个 agent 的交接处。上游的输出成为下游的输入，格式、范围、置信度、未决问题如果没写清，下游就拿着含糊输入往下生成，把错误一路放大。交付件要像接口一样设计：结论是什么，依据是什么，哪里不确定，哪些动作不能做，什么情况必须退回。这类机制在公司里叫流程，在工程里叫契约，名字不重要，约束重要。

还有授权和升级路径。一群 agent 不能凡事都问人，那只是把很多节点挂在一个人类瓶颈上；也不能让每个 agent 各自决定不可逆动作，那是失控。哪些决定由本岗位处理完，哪些向上交，什么触发上交，这些规则处理的是分工，不是人性——要留。

这三样是分工协作的骨架，不是装饰。它们也服务于求真：边界让责任清楚，交接让证据不断，授权让风险有门槛。一个团队如果连这些都没有，谈不上事实，只剩下互相生成。

## 组织表演要删

人类组织里还有一类机制，专门用来应对人的利益、面子、恐惧和权力欲：防抢功，防甩锅，防摸鱼，防站队，防上级不懂装懂还硬拍板。这个前提不能直接搬给 agent。

不要把表演当绩效。很多人类绩效制度是在信息不完整时评估人：看汇报，看态度，看谁在会上讲得清楚，看谁更会包装贡献。agent 团队不需要这套。它每一步工具调用、中间产物、返工路径、最终结果都能留痕，工作记录已经能查，就别再发明一套让 agent 讲述自己多努力的仪式。绩效来自 trace、产物和 eval，不来自汇报话术。系统越复杂，越要看真实工作记录，少看自我描述。

不要把审批当责任。层层审批一部分是协调，一部分是责任焦虑——多几个人签字，出了事看着就不只算一个人的。让多个 agent 都点过头，不等于责任处理好了；几个 agent 互相确认，也不等于事实更可靠。审批如果只是摊薄责任，不能改变风险，就只是在制造"大家都看过"的心理安慰，该删。有用的是授权边界和最终担责点：什么动作可以自动做，什么必须上报，谁有最终否决权。

不要让层级压过事实。这是人类组织最难删的病：懂的人没有裁决权，有裁决权的人不懂，事实碰到层级就让路。AI 进来不会自动消解它。如果把 agent 团队设计成僵硬层级，上级 agent 永远压过下级，那只是给旧病换了外壳。该让事实判断流向最接近事实的岗位——刚跑完 trace、见过错误、掌握上下文的 agent，可能比名义上的上级更懂那个局部。接不接受它的判断，是责任问题；但不能因为层级就否认它在局部事实上的优势。

不要把和气当协作。人类团队常把“大家意见一致”当成进展，agent 团队更容易这样。几个 agent 都说可以，不说明它们真的独立判断过。它们可能只是共享了同一段上下文，沿着同一个暗示往下写。协作不是互相点头，协作是每个岗位按自己的证据和责任说话。

这些补丁该删，和 agent 高不高尚无关。病因已经换了，旧病不该照搬，新病要另治。
