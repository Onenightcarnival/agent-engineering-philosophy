# 第八章：重新设计一种求真的团队

一群 agent，一群人和 agent，甚至一套几乎没有人参与日常操作的 agent 系统，最大的风险是把自己骗过去。

公司里的很多结构优先服务信息压缩、责任分摊、权力维持、情绪安抚和秩序感，事实反而退到后面。把这些东西照搬到 agent 系统里，只会得到一套会生成汇报、互相确认、层层审批，却不一定更接近事实的机器组织。

agent 改变了组织的底层条件。它能处理更大的材料集合，能临时生成隔离的判断岗位，能留下完整 trace，也能用更低成本重组能力。旧组织里的层级、流程和岗位，都要重新审计：它是在帮助事实流动，还是在复刻组织外壳；它是在降低风险，还是在制造责任表演。

有些机制必须保留。岗位边界、交接契约、授权路径、工作记录、最终担责点，这些来自协作本身。没有它们，团队会散。

有些机制必须删除。用汇报替代工作记录，用审批摊薄责任，用层级压过事实，用表演冒充绩效，这些来自人类组织的旧问题。agent 没有人类那套利益、面子和恐惧，不该继承这些补丁。

但只避免旧问题不够。agent 有自己的失败模式：迎合、同源重复、互相背书、把顺滑表达冒充正确判断。使用 agent 的人也会产生幻觉：把自己暗示出来的答案，当成系统独立判断。多 agent 系统不只要防 agent 出错，还要防人借 agent 自证。

求真的团队要靠机制设计出来：独立上下文、原始材料路径、批判权限、事实校验、可追溯记录、可撤回权限、可回滚结果，以及一个能承担后果的最终主体。
