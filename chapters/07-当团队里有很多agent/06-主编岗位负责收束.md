# 主编岗位负责收束

一群 agent 能不能写出好东西，取决于有没有主编岗位。

主编不是“再写一遍”的 agent。它决定哪些判断进入正文，哪些材料被舍弃，哪些批评必须处理，哪些局部正确不能破坏全文。

没有主编，多 agent 写作只会变成委员会写作。每个岗位都贡献一点，最后没有一句话负责到底。

## 主编守住中心判断

主编岗位先要守住中心判断。

一篇文章可以吸收很多意见，但不能同时拥有多个中心。立意 agent 可能提出一个锋利判断，批判 agent 会指出它的漏洞，素材 agent 又会带来另一个方向的例子。主编不需要让它们都满意，只需要判断这篇文章到底服务哪一个中心。

这就是主编和汇总器的区别。汇总器追求覆盖，主编负责取舍。汇总器怕漏，主编怕散。多 agent 系统里如果只有汇总器，没有主编，产出会越来越全，也越来越没判断。

## 主编也要听局部专家

主编有最终取舍权，但不代表它在所有局部都最懂。

事实错误，要听事实校验 agent；论证漏洞，要听批判 agent；语气漂移，要听风格 agent。主编不能用最终权力冒充局部判断力。它可以拒绝一个建议，但必须知道自己拒绝的是事实、风险、风格，还是和中心判断不相容的局部正确。

这里已经碰到下一章的问题：一群 agent 组成团队后，不能把人类组织里“位置压过事实”的病复制进来。主编岗位需要最终取舍权，但事实判断仍要流向最接近事实的岗位。

## 收束是责任，不是装饰

主编岗位不是层级装饰。它让产出有一个最终负责点。

文章发出去，读者不会追究“是哪一个 agent 写错了这一段”。他们看到的是一个整体。工程系统也是一样：工作可以拆，产出会合在一起，影响也会合在一起。影响一旦合起来，就必须有一个收束岗位对整体负责。

这就是多 agent 团队和多进程并行的区别。多进程只要各自算完，再合并结果；团队必须有人对整体判断负责。

到这里，第七章完成了多 agent 工程的基本图景：先设计岗位关系，再设计交接；按风险设授权和升级路径；隔离判断，共享必要上下文；用主编岗位收束整体。下一章处理另一件事：借用人类组织经验设计 agent 团队时，哪些该继承，哪些必须删掉。
