# 多 agent 写作不是并行生成

写作最容易暴露多 agent 的误用。

常见做法是把题目丢给几个 agent：一个写引言，一个写论证，一个写案例，一个写结论。各自生成一段，再把段落拼起来。看着分工明确，结果通常很差。这只是并行生成，离写作团队还远。

文章不是段落的集合。它有中心判断，有内部节奏，有取舍，有些话该说、有些话不该说。把这些拆散，再指望自动合起来，多半得到一篇每段都通顺、整体却没有判断的稿子。

## 拆判断，不拆章节

多 agent 写作要按判断功能拆岗位，不要按章节分包。

立意 agent 判断这篇到底要说什么。它不急着写漂亮句子，只把核心论点钉住。

结构 agent 安排论证顺序：先说什么、后说什么，哪里铺垫，哪里直接下判断。

批判 agent 找漏洞。它不负责让文章更圆滑，只挑偷换概念、论据不足、跑题和自我重复。

素材 agent 补材料。它不替文章定方向，只补足论证需要的事实、例子和反例。

风格 agent 统一语气。它不能改掉观点的锋利，只让表达更干净，更像一个人写的。

一个 agent 写一段，只是在分配体力；一个 agent 负责一种判断，才是在组建团队。

## 负责取舍的是主编

多 agent 写作最危险的地方，是每个 agent 都有一点道理。把每一点都保留下来，文章就成了观点展览。

批判 agent 找出的漏洞，不一定都要补进正文；素材 agent 找到的例子，不一定都值得留；风格 agent 给的圆润表达，也可能削掉文章的判断力。所以需要一个最终取舍点。没有它，每个岗位都会把自己的局部正确推向全文，文章就散了。

这个取舍点就是主编。它不负责再写一遍，负责决定哪些判断进正文、哪些材料舍弃、哪些批评必须处理、哪些局部正确不能破坏全文。

主编先守中心判断。一篇文章可以吸收很多意见，但只能有一个中心。立意 agent 抛出一个锋利判断，批判 agent 指出它的漏洞，素材 agent 又带来另一个方向的例子——主编不必让它们都满意，只需判断这篇到底服务哪一个中心。这就是它和汇总器的差别：汇总器怕漏，主编怕散。系统里只有汇总器、没有主编，产出会越来越全，也越来越没判断。

但有最终取舍权，不代表在每个局部都最懂。事实错误要听事实校验 agent，论证漏洞要听批判 agent，语气漂移要听风格 agent。主编可以拒绝一个建议，但得清楚自己拒的是事实、是风险、是风格，还是和中心判断不相容的局部正确。它不能拿最终权力冒充局部判断力。

## 取舍也是责任

主编岗位不是层级装饰，它让产出有一个最终负责点。

文章发出去，读者不会追究是哪个 agent 写错了哪一段。他们看到的是一个整体。工程系统也一样：工作可以拆，产出会合在一起，影响也会合在一起。影响一旦合起来，就得有一个岗位对整体负责。这正是多 agent 团队和多进程并行的分界——多进程各自算完、合并结果就行，团队得有人对整体判断负责到底。

到这里，第七章要讲的几件事都说完了：先设计岗位关系，再设计交接；按风险设授权和升级路径；隔离判断，共享必要上下文；用主编对整体负责。但这里还连着一个更大的问题——主编有最终取舍权，事实判断却该流向最接近事实的岗位，这两者怎么不打架。它已经走到下一章的门口：借用人类组织经验设计 agent 团队时，哪些该继承，哪些必须删掉。
