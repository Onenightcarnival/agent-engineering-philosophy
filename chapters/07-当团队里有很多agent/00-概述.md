# 第七章：当团队里有很多 agent

从一个 agent，到很多 agent。这一步常被叫做 multi-agent 编排，但那个词指向的是流程图——节点和连线。团队真正的内容不是连线，是岗位关系：谁负责什么、向谁交付、对谁的产出负责、谁能命令谁。

这一章用同一套人力资源视角看"很多 agent 在一起"。团队不是节点连线；协作的脆弱点在交接，不在节点；授权要配升级路径；可观测性会改写一批人类组织的老毛病；而把人类组织的机制移植过来，要带判断——保留协调机制，删掉人性补丁，同时给 agent 自己的新毛病另设机制。
