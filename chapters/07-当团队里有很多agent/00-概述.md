# 第七章：当团队里有很多 agent

从一个 agent，到很多 agent。这一步常被叫做 multi-agent 编排，但那个词指向的是流程图：节点和连线。团队真正的内容在岗位关系里：谁负责什么，向谁交付，对谁的产出负责，什么时候上报。

这一章只处理工程层的问题：一群 agent 怎么分工，怎么交接，怎么共享必要上下文，又怎么避免互相污染。写作会作为一个具体场景出现。写作很容易暴露多 agent 的误区：把一群 agent 同时放出去写，再把结果拼起来，通常只会得到一篇缝合稿。

多 agent 设计要把必须独立的判断岗位拆开，再设一个明确的收束岗位负责取舍。这里的“拆开”不是岗位越细越好，而是让事实校验、批判、执行、收束这些不能互相污染的判断保持距离。下一章再谈更高一层的问题：哪些人类组织经验可以继承，哪些人性失败规律不能复制。
